# Codex в kid: реализация и проверки

> Обновление: приложение переведено на защищённый native Windows runtime без Docker.
> Актуальная архитектура, запуск и границы защиты описаны в
> [native-codex-transition.md](native-codex-transition.md).
> Ниже сохранено историческое описание первоначального контейнерного адаптера.

27 октября 2026. App Server **0.164.0-alpha.11.1**, как у установленного
клиента. Параметры сверены с JSON Schema этой версии.

## Принудительный прокси

App Server и MCP-транспорт работают в Docker Desktop Linux-контейнере
`--network none`. До запуска launcher проверяет: только интерфейс `lo`,
отсутствие внешних IPv4/IPv6-маршрутов, UID 1000, нулевые capabilities,
`no-new-privileges`, корень read-only. Дочерний процесс реально пробует TCP и
UDP через IPv4/IPv6: все четыре попытки должны блокироваться ядром.

Внешний маршрут один: loopback proxy → stdio → хостовый broker → заданный
upstream. Broker реализует HTTP(S) CONNECT / SOCKS5 с удалённым DNS и открывает
сокет только к числовому IP upstream. Нет системного DNS, прямого fallback или
альтернативного маршрута. Реквизиты upstream не передаются контейнеру.
Основной worker допускает только HTTPS OpenAI/ChatGPT, исполнитель поиска —
публичные HTTP(S)-источники через тот же proxy. Потеря stdio/heartbeat завершает
контейнер и потомков. Неудачная проверка блокирует запрос с сообщением
«Прокси недоступен. Запрос Codex заблокирован». API-fallback отсутствует.

Образ закреплён по SHA256; исходники worker/инструментов сверяются с ним.
После их изменения требуется обновить образ. Подготовка использует уже
локальный Python Linux amd64 образ и официальный npm-пакет Codex, скачанный
только через proxy с проверкой SHA512. `docker pull` не вызывается.
Системный firewall и маршруты Windows не изменяются.

Граница гарантии — доверенные Windows, Docker Desktop/ядро и код launcher.
Это реальное ограничение сетевых путей kid, а не защита от администратора
или уязвимости ядра. Независимые клиенты Codex не охватываются интеграцией.
Сам proxy видит IP своего клиента. Облачный поиск сервиса выполняется на
его серверах и не маршрутизируется локальным proxy пользователя.

## Реализовано

| Возможность | Поведение |
| --- | --- |
| API / Codex | Старые профили остаются API; настройки движков сохраняются отдельно |
| Авторизация | Отдельный CODEX_HOME профиля; официальный ChatGPT device code |
| Браузер входа | Не открывается; код и адрес показаны текстом для другого устройства/защищённого браузера |
| Модели | Реальный model/list и поддерживаемые моделью reasoning efforts |
| Proxy | Отдельный для профиля, write-only пароль, состояние и проверенный выходной IP |
| Квоты | account/rateLimits/read, уведомления, минутное обновление, время и stale-кеш |
| Чат | Поток ответа/событий, остановка, подтверждения команд/файлов, конечные бюджеты |
| Авторазрешение | Переключатель профиля принимает только команды активного хода; файлы, дополнительные права и network approvals требуют подтверждения |
| Лента работы | Commentary отделён от final_answer; живые события, раскрываемый вывод команд, свёрнутая лента и фактическое время после завершения |
| Windows | Реальное создание новых файлов на Desktop/в проекте и закрытый набор диагностик ipconfig; общий shell заблокирован до сетевой изоляции ОС |
| История | Отдельные привязки диалогов, resume, журналы operation/turn ID |
| Повторы | Завершённый запрос возвращает кеш; неизвестный исход требует восстановления |
| MCP | Локальный stdio, общий исполнитель, журнал побочных действий на хосте |
| Инструменты | Заметки, память, поиск, чтение, локальный поиск и создание TXT/PY/DOCX |
| Поиск Codex | Встроенный поиск; сетевые поисковые инструменты kid скрыты и отклоняются |
| Поиск kid | Встроенный поиск, универсальные shell/code mode/браузер выключены; поиск/чтение через MCP |
| Исследование | Модельный контроллер использует этот же App Server, без платного API |
| Панель проекта | Выбор папки, файлы, текст, Git diff, события команд/изменений, открыть VS Code |
| Сайты | Запросы/ссылки в шагах, чтение текста явно отличается от визуального открытия |

Журналы привязок/действий не смонтированы в проект. App Server не получает
API-ключи kid. Поисковому исполнителю передаётся только нужный ключ Serper.
Сырые stderr не выводятся; события очищаются от паролей, токенов и URL с
реквизитами. Незнакомые server requests отклоняются. Изменения заметок обновляют UI.

## Проверено

- 176 Python-тестов: API/профили, реальный HTTP-мост, протокол, квоты, секреты,
  изоляция диалогов, восстановление и запрет повтора при неизвестном исходе.
- TypeScript и production-сборка Next.js; Chromium smoke с настоящим временным
  backend: блокировка неготового Codex, сохранение черновика, квоты, файлы,
  сохранение/перезагрузка профиля, пароль write-only, переключение движка.
  В smoke используется тестовая переадресация вместо Next proxy route.
- Добавленный интерфейс приведён к существующим Select/Button/FieldGroup,
  Sheet/Dialog и оформлению настроек, заметок, логов и шапки. Новые CSS,
  палитра и тема не добавлялись. Проверены 1440×1000 и 390×844, отсутствие
  горизонтального переполнения панелей, закрытие панели, выбор поиска,
  модели и effort. Доступные модели/device code в этой UI-проверке подставлены
  явно тестовым локальным ответом, реальная авторизация не выполняется.
- Настоящие HTTP и SOCKS proxy из приватного конфига: проверенный TLS,
  выходной IP **<IP ??????>**. Прямой исходный IP не запрашивался.
- Реальный worker: четыре заблокированных прямых IPv4/IPv6 TCP/UDP попытки,
  отсутствие внешних интерфейсов, App Server initialize и каталог 8 моделей.
- Реальный thread/start без генерации принял MCP/approval/sandbox config.
  JSON Schema содержит используемые clientUserMessageId, device code и квоты.
- MCP фильтрует инструменты; отдельный worker создал временный документ и
  прочитал текст example.com через proxy.
- Linux-зависимости установлены через proxy. LanceDB/FastEmbed проверены на
  временных фактах: модель из существующего локального кэша, без скачивания,
  настоящая база пользователя не менялась.
- GitHub metadata и Serper реально проверены через proxy. Подключение
  модельного контроллера проверено с явно тестовым callback, без настоящей
  генерации: эта проверка не оценивает качество ответов модели.
- Git diff выполняется только внутри проверенного контейнера; на хосте Git
  из панели не запускается. Реальный временный репозиторий подтвердил diff
  и отсутствие запуска внешних diff/fsmonitor helpers. Lazy fetch и внешние
  Git-протоколы дополнительно запрещены. Неподтверждённая отмена сохраняет
  неизвестный исход и запрещает повтор до восстановления.
- Недоступный proxy, HTTP 407 и разрыв TLS: по одной попытке к proxy, ноль
  прямых попыток хоста, запрос заблокирован. Эти проверки выполняются только
  после подтверждения блокировки сети ядром. Потеря heartbeat завершает worker.

После ручного подтверждения device code пользователем проверено восстановление
аккаунта в двух последовательно запущенных новых App Server: оба вернули
authenticated без account/login/start. В каждом запуске прокси проверен,
четыре попытки прямого выхода заблокированы ядром. Запросов генерации — ноль.
CODEX_HOME профиля сохраняется через постоянный bind mount; официальный
cli_auth_credentials_store=file хранит авторизацию между запусками.
Выбранный профиль автоматически подключается при запуске приложения и при
переключении на Codex; при подтверждённом входе лишние кнопки входа скрыты.

Генерация, отмена и resume с реальным аккаунтом, принудительное истечение
токена и разрыв прокси во время генерации отдельно пока не проверены.
Маршрутизация действует для всех RPC, но не заменяет функциональные проверки.
Отзыв авторизации сервисом или явный выход потребуют повторного входа по коду.

## Ограничения

- Нужен локальный Docker Desktop Linux amd64; при его отсутствии запуск запрещён.
- Linux shell отключён: Windows-действия выполняют отдельные закрытые MCP-инструменты
  на компьютере пользователя. Общий CMD/PowerShell требует отдельной изоляции ОС;
  см. [границы и порядок настройки](windows-local-actions.md).
  После перезапуска папку проекта нужно снова выбрать системным диалогом.
- Поиск kid требует Serper. Локальный SearXNG хоста не подключается из контейнера;
  универсальные команды выключены для принудительного выбора поискового маршрута.
- Вложения чата и Document Studio остаются в API. Codex использует выбранную
  папку проекта и существующий инструмент создания файлов TXT/PY/DOCX.
- Память LanceDB требует Linux-зависимостей. Без них доступ к существующей
  нативной базе блокируется, а не создаёт параллельную JSON-базу.
- VS Code открывает независимую сессию расширения. Встроенного браузера нет.
- При потерянном ответе невозможно угадать исход побочного эффекта: повтор
  блокируется до восстановления вместо автоматического переисполнения.

## Запуск

В приватном конфиге создан отдельный профиль **Codex** с сохранённым proxy.
Активный профиль и остальные профили не менялись.

1. Запустить Docker Desktop с Linux-контейнерами.
2. Перезапустить kid через [start.bat](../start.bat), выбрать профиль Codex.
3. В настройках нажать «Подключить через прокси» и «Войти в ChatGPT».
4. Подтвердить код на другом устройстве или в браузере с принудительным proxy;
   kid браузер не открывает. Выбрать модель/effort из реального списка.
5. Для кода выбрать папку через кнопку проекта в шапке. Поисковый режим сохранять
   в профиле. При неизвестном результате — «Восстановить предыдущий ход».

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe scripts/prepare_codex_runtime.py --use-app-proxy
.\.venv\Scripts\python.exe scripts/prepare_codex_tools.py --use-app-proxy
.\.venv\Scripts\python.exe scripts/check_codex_isolation.py --use-app-proxy
.\.venv\Scripts\python.exe scripts/check_codex_failures.py
.\.venv\Scripts\python.exe scripts/check_codex_memory.py
.\.venv\Scripts\python.exe scripts/check_codex_tools.py
.\.venv\Scripts\python.exe scripts/check_codex_diff.py
.\.venv\Scripts\python.exe scripts/check_codex_account.py --profile-id codex --login
.\.venv\Scripts\python.exe -m unittest discover -s tests
npm.cmd --prefix UI run typecheck
npm.cmd --prefix UI run build
.\.venv\Scripts\python.exe scripts/check_codex_ui.py
```

Подготовка зависимостей требует ≥16 ГиБ свободного места, останавливается при
временных данных >2 ГиБ или свободном месте <12 ГиБ.

Официальные источники: [App Server](https://developers.openai.com/codex/app-server),
[Codex MCP](https://developers.openai.com/codex/mcp),
[MCP stdio](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports),
[Docker network none](https://docs.docker.com/engine/network/drivers/none/).
