# Установка и обновления Windows

## Пользователь

Предпочтительный вариант — `kid-setup.exe` из GitHub Releases. Он содержит загрузчик
PowerShell, поэтому запуск не требует установленного Python, Node, Git или сборщика C#.
Нужны Windows 10/11 x64, Windows PowerShell 5.1, интернет и место для зависимостей.
Это сетевой установщик: первый запуск скачивает довольно большой набор библиотек и Chromium.

1. Загрузчик получает последний стабильный релиз `ShradAp/kid`, проверяет `SHA256SUMS`,
   проверяет пути в ZIP и распаковывает архив в новую папку с уникальным именем.
2. Версия сама выполняет свой `install.ps1 -ManagedRuntime`. Версии сред определены
   в [runtime.json](../installer/runtime.json), библиотеки — в
   [requirements.txt](../requirements.txt) и [package-lock.json](../UI/package-lock.json).
3. Python ставится через закреплённую версию uv, Node — из официального ZIP. SHA-256
   проверяется по контрольным суммам поставщиков через HTTPS. WebView2 устанавливается
   официальным загрузчиком после проверки действительной подписи Microsoft.
   Недостающий Visual C++ Runtime также устанавливается с проверкой подписи; Windows
   запрашивает UAC. Если необходима перезагрузка, установщик просит перезагрузить ПК и повторить попытку.
4. Выполняются установка библиотек, `pip check`, проверка основных импортов и запуск Chromium,
   `npm ci` и полноценная сборка интерфейса. Успех отмечается только после всех команд.
5. Атомарная замена `current.json` переключает текущую версию. Предыдущий указатель
   сохраняется. Созданный ярлык запускает текущую версию, включая её частный Node.

Старая работающая программа может оставаться открытой во время установки новой версии.
После успеха её нужно полностью закрыть через трей, затем открыть ярлык на рабочем столе.
Установщик не завершает процессы пользователя. Уже запущенное окно использует прежний код
до перезапуска. Двойной запуск установщика блокируется эксклюзивным файловым дескриптором;
после аварийного завершения Windows освобождает его автоматически.

## Повторная попытка и откат

После ошибки повторно запустите EXE. Незавершённая папка никогда не становится текущей.
Загрузки используют `.part`; подготовка Codex проверяет архив в кэше и заново скачивает
повреждённый. Исполняемые файлы и метаданные Codex записываются через временные файлы
с атомарной заменой. Занятый компонент приводит к понятной ошибке с просьбой закрыть kid.
Проверка хешей и WFP остаётся обязательной до запуска Codex.

Рабочие версии, неудачные попытки, среды и журнал находятся в `%LOCALAPPDATA%\kid-launcher`.
Неудачные попытки пока сохраняются для диагностики и занимают место; автоматическая
очистка старых версий не реализована. Личные данные — в `%APPDATA%\kid`; их переустановка
и откат не удаляют. Старый установщик в исходниках также сохраняет непригодные окружения
и неполные сборки под именами `.venv.failed-*` и `UI/.next.failed-*`.

Для отката к предыдущей успешно установленной версии сначала закройте kid через трей:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:LOCALAPPDATA\kid-launcher\loader.ps1" -Rollback
```

Откат меняет только программу. Обратная совместимость будущих миграций личных данных
должна проверяться отдельно; перед изменением формата данных добавляйте резервную копию.

## Прокси и диагностика

Загрузчик не может исправить недоступный сервер, неверный пароль или отсутствие системного
прокси. Установка приложения использует сетевую конфигурацию Windows/инструментов установки;
защищённый транспорт Codex по-прежнему требует прокси, сохранённый в общих настройках kid.
Параметры и секреты с компьютера автора не включаются в релиз.
Режим «Авто» сработает у другого человека только при наличии его собственного системного прокси.
Для ручного режима Codex нужен IP-адрес и порт; при первом подключении нужно подтвердить UAC.

Проверка GitHub из настроек использует requests и сетевое окружение процесса; настройки
защищённого Codex к ней не применяются. Если GitHub/PyPI/npm заблокированы, установка
остановится с ошибкой. Абсолютной гарантии отсутствия сбоев сети/диска/антивируса нет.
Используются TLS и контрольные суммы, полученные из того же доверенного источника;
это проверка целостности, а не независимая цифровая подпись релиза. EXE пока не подписан
сертификатом издателя и может вызвать предупреждение Windows SmartScreen.

При проблеме сохраните текст ошибки и `loader.log`; для ошибок приложения —
`%APPDATA%\kid\last_error.log` и `error.log`. Секреты перед отправкой журнала нужно скрыть.

## Автор релиза

Локальная сборка EXE без установки дополнительного компилятора:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build_installer.ps1
```

Результат: `dist/kid-setup.exe`. Этот файл скачивает **опубликованный** релиз, а не текущие
несохранённые файлы разработчика. Для установки текущей распакованной копии есть `setup.bat`.

Для выпуска закоммитьте все необходимые файлы и отправьте изменения в GitHub, затем
создайте и отправьте новый тег `vX.Y.Z`. [Workflow](../.github/workflows/release.yml)
проверяет установку с управляемыми средами на Windows runner, тесты и сборку EXE,
создаёт ZIP через `git archive`, публикует EXE, ZIP и `SHA256SUMS`.
Workflow можно повторить вручную на теге при сбое инфраструктуры.
Пользовательские настройки и локальное окружение в архив не попадают.

Для будущих изменений сохраняйте интерфейс `install.ps1 -ManagedRuntime`,
`installer/loader.ps1 -LaunchOnly/-ReleaseTag/-NoLaunch/-Rollback` и схему 1 указателя.
Загрузчик обновляется из проверенного нового релиза вместе с программой.
При изменении Python, Node или зависимостей обновляйте манифест/lock-файлы и тестируйте
первую установку, обновление, оборванную загрузку и откат на чистой Windows.
Для необратимых изменений протокола загрузчика нужен отдельный план миграции.
