# Операции на компьютере Windows

> Обновление: ограничения только на ipconfig и обязательный Docker сняты при
> переходе на native Windows runtime. Актуальная реализация PowerShell/CMD,
> подтверждений, файлов и прокси описана в
> [native-codex-transition.md](native-codex-transition.md).
> Ниже — историческое обоснование прежней, более широкой границы сетевой изоляции.

Codex App Server остаётся внутри Linux-контейнера без внешней сети. Это транспорт
модели, а не рабочий стол пользователя. Встроенный Linux shell отключён в обоих
режимах поиска. Модель получает явную инструкцию различать Windows и контейнер.

## Доступные операции

- `windows_write_file` создаёт новый TXT, MD, CSV, JSON или DOCX на настоящем
  рабочем столе Windows (включая перенаправление OneDrive) или в выбранном проекте.
  Требует подтверждения, не перезаписывает файлы, не принимает вложенные пути,
  UNC, junction, ADS, зарезервированные имена и исполняемые расширения.
- `windows_command` запускает только системный `ipconfig.exe` с пустыми аргументами
  или `/all`. Shell не используется. `/renew`, `/registerdns`, подстановка команд,
  PowerShell и произвольные программы отклоняются до создания процесса.
  Переключатель авторазрешения относится к этим поддерживаемым диагностикам.
- Созданные через обычный инструмент downloadable-файлы также физически лежат
  в данных kid на Windows; это не означает размещение на рабочем столе.

## Почему общий CMD/PowerShell пока отключён

Произвольный процесс под обычной учётной записью Windows может самостоятельно
открыть соединение, запустить сетевого потомка или обойти переменные прокси.
Запуск такого процесса без отдельной политики ОС нарушил бы обязательное
требование отсутствия прямого трафика. Подтверждение команды это не исправляет.

Для полного режима необходим отдельный исполнитель Windows:

1. Отдельная ограниченная идентичность ОС или AppContainer без сетевых capabilities;
   никаких сохранённых аккаунтов, паролей прокси и секретов API в этой среде.
2. Доступ записи только к явно выбранным пользовательским папкам. Работа с файлами
   должна менять реальные Windows-папки, а не внутренние каталоги контейнера.
3. Запрет исходящего IPv4/IPv6 TCP/UDP для всей идентичности исполнителя и потомков
   через механизм ОС. Правило для одного executable недостаточно. Сетевые операции
   разрешены только через существующий отдельный брокер со строгим прокси; IPC — stdio.
4. Проверки отказа на локальных контролируемых сетевых приёмниках, проверки дочерних
   процессов и DNS до разрешения запросов к внешним сервисам. Затем проверка обрыва
   прокси при работающем прямом интернете и повторного запуска.
5. Только после успешной проверки — включение общего CMD/PowerShell в профиле.

Эта настройка ОС не выполнена и требует отдельного согласования. Текущее приложение
не меняет firewall, системные маршруты, пользовательские ACL и учётные записи Windows.

## Ошибки связи и история

API загрузки истории возвращает `activity`, `thinking` и `reasoning`, чтобы оформление
Codex сохранялось после запуска. Локальный Next→Python транспорт не использует
ограничение fetch на ожидание заголовков длительного хода. При ошибке хода выставляется
отмена, ожидающие подтверждения удаляются; автоматического повторного исполнения нет.
