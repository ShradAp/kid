# Проверка стабильности kid — 27 октября 2026

Область: основной чат, профили, хранение истории и заметок, поиск, память,
локальный HTTP-мост и интерфейс. Document Studio, его компоненты и обработчики
не изменялись. Форматы существующих данных сохранены.

## Исправления

- История обычного чата: параллельные записи больше не делят один `.tmp`.
  Запись сериализована, временный файл отдельный для потока, выполняются flush,
  fsync и атомарная замена. При ошибке замены предыдущая история сохраняется,
  временный файл очищается. Методы истории Studio не менялись.
- Миграция старых чатов: уже перенесённый файл больше не читается и не
  разбирается заново при каждом `load_config()`. Проверяется наличие целевого
  файла; новые старые истории по-прежнему могут быть перенесены.
- Заметки: атомарные записи защищены блокировкой, добавление заметки выполняет
  чтение/изменение/запись под одной блокировкой. Ошибка диска больше не выдаётся
  за успешное сохранение.
- Интерфейс загружает заметки отдельным лёгким запросом вместо второго
  `/api/init`, который повторно читал все диалоги и мог обновлять баланс.
- Последовательная очередь сохранения заметок исключает приход старого
  полного снимка после нового. Начальная загрузка и восстановление кэша
  не считаются редактированием и не перезаписывают сервер автоматически.
  Заметки, добавленные до завершения загрузки, объединяются по ID.
- Ошибка сохранения заметок видна пользователю. Сообщение о локальной копии
  показывается только если запись в localStorage действительно удалась.

## Проверки

- **176 Python-тестов**, включая пять новых регрессий: конкурентная запись
  истории, сохранность при ошибке замены, отсутствие повторного чтения старой
  истории, конкурентное добавление заметок и ошибка записи заметок.
- Production-сборка Next.js с проверкой TypeScript.
- Chromium с настоящим временным backend: одна полная загрузка состояния,
  заметки без лишней стартовой записи, искусственный отказ диска, уведомление,
  локальная копия, восстановление сохранения обеих заметок, запрет автоматической
  перезаписи сервера кэшем при неудачном GET. Существующие проверки профилей,
  файлов и интерфейса также прошли.
- После изменения общего Python-модуля обновлён защищённый образ Codex;
  реальная проверка ядра, прокси, App Server, MCP и временного документа прошла.
  Генерация и вход в аккаунт в этой проверке не выполнялись.

Тесты хранения и браузерные изменения использовали временный каталог данных.
Реальные диалоги, заметки и факты пользователя для стресс-тестов не менялись.

## Границы результата и наблюдения

Это проверка покрытых сценариев, не доказательство отсутствия любых ошибок.
Реальные платные запросы к API-провайдеру не отправлялись; доступность внешних
сайтов, мультимедиа и модели зависит от сервисов и форматов источников.

В общем API-клиенте осталась старая политика повторов: после ReadTimeout запрос
может отправляться повторно, а названия маршрутов в диагностике не соответствуют
`trust_env=False`. Это не меняет строгий маршрут отдельного движка Codex.
Транспорт используется и Studio, поэтому в рамках этой проверки его поведение
не менялось. Политику повторов основного API-чата полезно впоследствии отделить
от Studio и проверять на локальном провайдере с потерянным подтверждением.

Крупный перенос функций из монолитного backend и замена существующих сетевых
адаптеров не выполнялись: для этой проверки выбраны локальные исправления с
воспроизводимыми регрессиями.

## Исправление запуска WEB_UI

Повторный запуск завершался из-за занятого порта 3000: предыдущий экземпляр
продолжал работать со скрытым окном Assistant. Ассоциация `.pyw` также выбирала
системный Python 3.14 вместо окружения проекта Python 3.12.

- Лаунчер сначала выбирает `.venv`, а ошибки импорта и старта показывает
  диалогом с путём к журналу.
- Mutex и событие Windows, привязанные к пути проекта, позволяют повторному
  запуску восстановить существующее окно, в том числе во время его загрузки.
  Сетевые команды и файлы с токенами для этого не используются.
- HTTP-мост использует SO_EXCLUSIVEADDRUSE: второй мост не может разделить
  тот же порт на Windows.
- Три регрессионных теста проверяют выбор окружения, активацию окна через
  событие, освобождение mutex после аварийного выхода и эксклюзивность порта.
  Тестовые mutex изолированы от настоящего приложения.
- Выполнен реальный запуск через системный Python: окружение проекта выбрано,
  окно видно, страница отвечает HTTP 200. Повторный запуск восстановил то же
  предварительно скрытое окно; приложение оставлено открытым.

Маршрутизация Codex и Document Studio в этом исправлении не изменялись.
