# Общая библиотека расширений kid

В общих настройках откройте «Расширения», выберите тип и укажите абсолютный путь к локальному источнику. Просмотр показывает источник, описание, состав и параметры запуска до добавления. Добавление и сохранение настроек не выполняют команды. Для MCP отдельная кнопка «Запустить и проверить MCP» запускает указанную установленную программу и проверяет `initialize` и `tools/list`.

После добавления отметьте расширение в нужном профиле. В существующем профиле галочки сохраняются сразу, без общей кнопки сохранения. Новый профиль нужно сначала сохранить один раз. Открытая форма настроек обновляет библиотеку каждые полторы секунды, поэтому добавленные агентом скиллы появляются автоматически.

Новый набор применяется перед следующим сообщением. Текущий ответ продолжает использовать прежний снимок. Codex создаёт штатную ветку `thread/fork` с полной историей и новым набором инструментов, затем продолжает тот же чат kid. История и журнал выполненных операций сохраняются; пересказ последних сообщений вместо полной истории для этого сценария не используется. При восстановлении запроса с неизвестным исходом сохраняется прежний набор до завершения восстановления. Перезапуск приложения или ручной перезапуск чата не требуются.

## Установка по запросу модели

В нативном Codex доступен встроенный инструмент `install_skill`. По прямому запросу пользователя агент вызывает `action=inspect`, сообщает источник и состав, затем `action=install` с полученным отпечатком. Источники: локальная папка/файл, ссылка на папку скилла в публичном GitHub-репозитории, ссылка skills.sh или запись `owner/repo@skill`. Неоднозначный репозиторий с несколькими скиллами требует указания конкретной папки.

Импорт фиксирует GitHub commit, проверяет пути, лимиты размера и число файлов, отклоняет ссылки и подмодули. Скачиваются только файлы выбранного скилла; npm, npx и сценарии пакета не запускаются. Изменение файлов между просмотром и установкой требует повторного просмотра. Повторное добавление того же источника возвращает существующую запись. Инструмент не меняет выбор ни одного профиля: пользователь сам включает скилл галочкой. Скачивание по ссылке относится к скиллам; MCP и плагины по-прежнему добавляются из локальных источников.

## Источники

- **Скилл:** `SKILL.md` либо его папка. YAML содержит `name`, `description`, необязательные `version`, `dependencies` (ID библиотеки). Пользовательское название и описание можно переопределить перед добавлением. Ресурсы копируются вместе с инструкцией; предел — 20 МБ и 1000 файлов. Символьные ссылки и junction внутри пакета не поддерживаются.
- **MCP:** JSON-файл либо папка с `mcp.json`. Поддерживается stdio с установленным исполняемым файлом по абсолютному пути. `mcp_servers` и `mcpServers` поддерживаются. HTTP/SSE, OAuth-подключение и установка зависимостей не реализованы.
- **Плагин:** папка с `kid-extension.json` либо сам манифест. Поддерживается только явно описанный формат `kid-extension-v1`. Форматы других приложений, hooks и установочные сценарии не исполняются и не считаются поддерживаемыми компонентами.

Пример MCP:

```json
{
  "name": "Документы",
  "description": "Поиск и чтение документов",
  "mcp_servers": {
    "documents": {
      "command": "C:/tools/documents/server.exe",
      "args": [],
      "env_from": { "API_KEY": "DOCUMENTS_API_KEY" }
    }
  }
}
```

`command` указывает на программу, `args` — массив аргументов, `cwd` — необязательную рабочую папку. `env_from` сопоставляет переменные сервера с именами секретов kid или переменных окружения приложения. Значения задаются в форме «Настроить» существующим полем секретов; пустое поле сохраняет прежнее значение, удаление требует отдельного действия. Как и другие секреты текущего приложения, они хранятся в пользовательских настройках; это не новое шифрованное хранилище. Значения не включаются в каталог, описания, снимки расширений или обычные сообщения об ошибках. Аргументы команд и пользовательские описания не предназначены для секретов.

Пример плагина:

```json
{
  "format": "kid-extension-v1",
  "name": "Работа с PDF",
  "description": "Чтение PDF и поиск в документах",
  "version": "1.0",
  "dependencies": [],
  "skills": ["skills/pdf"],
  "mcp_servers": {
    "documents": {
      "command": "C:/tools/documents/server.exe",
      "args": []
    }
  }
}
```

Пути скиллов относительны манифесту и должны оставаться внутри пакета. Зависимости задаются постоянными ID из «Подробнее». Учитываются также явно объявленные MCP-зависимости `agents/openai.yaml`: `dependencies.tools` с `type: mcp` и `value`, равным имени компонента `mcp_servers`. Другие типы таких зависимостей показываются как неподдерживаемые. Из текста инструкций зависимости не выводятся.

## Передача агенту

Поддерживается защищённый Windows Codex App Server. API-провайдеры и Document Studio показывают статус отсутствия поддержки; выбор сохраняется, но инструменты им не передаются.

Скиллы передаются кратким каталогом с ID, названием и описанием. MCP-инструмент `kid_skills.read_skill` читает полную инструкцию по запросу; необязательный параметр `resource` читает текстовый ресурс внутри этого же скилла. Для записи с одним скиллом поддерживается также ID самой записи библиотеки, который возвращает установка. Автоматическое выполнение скриптов скилла отсутствует.

MCP регистрируется штатным `thread/start` / `thread/resume` через `config.mcp_servers`. Подключения необязательны (`required: false`), имеют отдельные пространства имён, стабильный порядок и ограниченные таймауты. Идентичные параметры подключения регистрируются один раз; дубли имён инструментов внутри сервера отклоняются. Идентичные скиллы из одного источника в нескольких пакетах также регистрируются один раз. Встроенный MCP kid сохраняется. Неявно обнаруженные скиллы, MCP и плагины из настроек Codex отключаются в контексте управляемой сессии.

Ошибки проверки и уведомления App Server об ошибках запуска MCP показываются отдельно. Для обновления состояния открытой формы есть кнопка «Обновить состояние». «Готово» для MCP означает успешную проверку протокола и списка инструментов; успешность конкретного действия подтверждается его результатом в чате.

MCP-процессы запускаются как локальные программы и могут выполнять код и использовать обычную сеть Windows. Защита транспорта Codex не превращает внешние MCP в изолированные программы.

## Хранение и проверки

Каталог и выбор сохраняются существующим механизмом настроек: `extensions`, `profiles.<id>.extension_ids`. Существующие профили без выбора получают пустой набор. Установленные инструкции и ресурсы находятся в пользовательской папке `extensions`, снимки сессий — в `extension_sessions`; указатель на снимок хранится в привязке чата. При удалении очищаются ссылки всех профилей, а копии открытых сессий сохраняются. Библиотека включена в существующий файловый бэкап kid.

Автоматические проверки: `python -m unittest discover -s tests -p test_extensions.py`, `test_skill_imports.py`, существующие тесты Codex/настроек/HTTP и сборка UI. Тесты расширений запускают настоящий локальный stdio MCP и проверяют вызов с результатом без обращения к аккаунту или внешней сети. Браузерная проверка `scripts/check_extensions_ui.py` проверяет появление скилла в уже открытой форме и сохранение галочек без общей кнопки сохранения.

Дополнительно проведён ручной сквозной тест на реальном Codex: модель установила `web-design-guidelines` из публичного репозитория Vercel штатным `install_skill`; скилл остался выключенным. После изменения галочки в том же чате агент прочитал полную инструкцию через `read_skill`; после отключения скилл исчез из актуального каталога. Между сообщениями приложение не перезапускалось, история сохранялась штатным `thread/fork`. Тестовая запись оставлена в библиотеке выключенной; исходный выбор профиля восстановлен.
