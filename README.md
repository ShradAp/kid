# Sprut / kid

Codex: официальный App Server непосредственно в Windows, принудительный прокси,
отдельные профили, локальный MCP и лёгкая панель проекта. Docker и Proxifier для
Codex не нужны. При первом подключении kid сам подготавливает компоненты через
прокси и запрашивает однократное подтверждение Windows для защитных правил.
Без подтверждённой защиты запрос блокируется до запуска Codex.
[Устройство защиты, проверки и ограничения](reports/native-codex-transition.md).

Локальный AI-ассистент для Windows: чат, поиск, память профиля, вложения и студия DOCX.
Для API нужен ключ OpenAI-совместимого провайдера; Codex использует аккаунт ChatGPT.

## Установка на новом компьютере

Требования: Windows 10/11 x64, Python 3.12+ x64, Node.js 22+ и Microsoft Edge WebView2 Runtime.
Проверки текущей интеграции выполнены на Python 3.12 и установленном Node.js.
Python и Node.js должны быть доступны через PATH. Установка требует интернета и свободного места
для Python-пакетов и Chromium. Обычный запуск не требует прав администратора;
однократная установка защиты Codex требует системного подтверждения UAC.

Откройте PowerShell в папке скачанного проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

Установщик создаёт `.venv`, устанавливает библиотеки из `requirements.txt`,
скачивает Chromium для Playwright, выполняет `npm ci` и сборку интерфейса.
При ошибке установка останавливается с сообщением. WebView2 Runtime при его отсутствии
нужно установить отдельно с сайта Microsoft: https://developer.microsoft.com/microsoft-edge/webview2/.

Запуск: двойной щелчок по `start.bat`. Он всегда использует Python из `.venv`;
ассоциация `.pyw` с другим системным Python не влияет на запуск.
В профиле укажите адрес провайдера, модель и свой API-ключ. У проекта нет общего ключа.
Не запускайте интерфейс отдельно через `npm run dev`: ему нужен внутренний токен Python-процесса.
Для разработки задайте `$env:KID_FRONTEND_DEV='1'`, затем запустите `start.bat`.

## Где находятся личные данные

При первом запуске автоматически создаётся `%APPDATA%\kid` — обычно
`C:\Users\<имя>\AppData\Roaming\kid`. Это профиль текущего пользователя, а не жёстко заданный диск C.
Путь меняется вместе с расположением профиля Windows; для отдельного экземпляра можно задать `KID_CONFIG_DIR`.

- `config.json`: настройки, профили и ключи провайдеров;
- `history`, `studio_history`: история чатов, файлы появляются при сохранении сообщений;
- `notes.json`: заметки, файл появляется после сохранения;
- `data`: база памяти;
- `generated_files`, `presets`: документы и пользовательские пресеты;
- `.backups`: приватные резервные архивы, включающие ключи и переписку;
- `.env`: необязательные секреты окружения, журналы находятся рядом.

Исходники не содержат ваших настроек. Не публикуйте каталог данных и резервные архивы.
Модель памяти хранится отдельно в `%LOCALAPPDATA%\kid\fastembed` и может скачаться при первом запуске.
Без доступной модели память переходит на запасной локальный режим. Модель распознавания речи
также загружается при первом использовании. Диалоги и выбранные вложения отправляются указанному
в профиле AI-провайдеру; поисковые запросы — выбранному поисковому сервису.

## Локальный поиск SearXNG — необязательно

Нужен Docker Desktop. Если `.env` уже существовал до обновления и не содержит `SEARXNG_SECRET`,
добавьте туда отдельное случайное значение, например результат `python -c "import secrets; print(secrets.token_hex(32))"`.

```powershell
docker compose --env-file "$env:APPDATA\kid\.env" -f .\searxng\docker-compose.yml up -d
```

Сервис доступен только на `127.0.0.1:8080`; секрет берётся из личного окружения,
как описано в [документации SearXNG](https://docs.searxng.org/admin/settings/settings_server.html).
Для поиска через Serper укажите свой ключ в настройках. Его можно использовать без Docker.

## Проверки и восстановление

### Поиск с несколькими раундами исследования

Markdown-отчёты проверок находятся в `reports/`. Сырые JSON-выгрузки страниц,
расшифровок и метрик остаются локальными и исключены из Git; их создают скрипты
из `scripts/`. Ссылки на эти JSON в отчётах доступны после локального запуска проверок.

Оба входа веб-поиска используют общий модуль [research_search.py](research_search.py).
Он собирает выдачу SearXNG и Serper, переходит на следующие страницы, читает
источники и уточняет запросы по найденным названиям. В чате отдельный контекст
текущей модели оценивает соответствие объекту, прямые подтверждения, качество
источников и противоречия, затем выбирает запрос и площадку под конкретный пробел,
чтение найденной страницы или завершение. Эта модель не получает инструменты и
историю личной переписки: основная модель передаёт самостоятельное задание `objective`.
Ошибка планировщика
не останавливает поиск: остаются пагинация и локальное извлечение названий.

Стандартный бюджет одного вызова с публичными площадками: до 20 обращений к поисковым каналам,
12 чтений порциями до трёх, 3 запросов к модели-планировщику, 4 раундов, 3 страниц на запрос
в каждом канале, 140 уникальных URL и 120 секунд. Без публичных направлений
(`include_public=False`) базовый бюджет — 12 обращений, 80 URL и 90 секунд. Это лимиты работы,
а не гарантия денежной стоимости: тарифы зависят от выбранных провайдеров.
Параметр профиля `search_results` ограничивает количество возвращаемых
источников, а не число исследуемых URL. Программно бюджет задаётся через
`SearchBudget` и аргумент `web_search(..., budget=...)`.

В «Настройки → Поиск → Режим исследования» доступны два режима:
`adaptive` (по умолчанию) сохраняет исследовательскую беседу с предыдущими материалами
и оценками; `isolated` каждый раз начинает новую беседу той же модели с отдельным
промптом, заданием, компактной памятью выводов со ссылками, пробелами, противоречиями,
историей запросов и остатком бюджета. Переключатель сохраняется в общем параметре
`search_research_mode` и применяется со следующего вызова поиска. Реализация —
[research_controller.py](research_controller.py). Ни один режим не передаёт оценщику
полную переписку пользователя. Вызовы модели используют API активного профиля.

Остановка по достаточности требует указанных оценщиком выводов и подтверждающих URL
из действительно прочитанных, релевантных, недублирующихся материалов, без отмеченных
пробелов и противоречий. Сниппеты и описания видео не подходят. Код проверяет структуру
и ссылки; истинность и полнота ответа остаются оценкой модели, а не гарантией.
`report.assessments` содержит оценки и отклонённые попытки завершения. Ошибка модели
оставляет обычный поиск в пределах исходного бюджета; без настроенного API работает
эвристический поиск. Лимиты и отмену модель изменить не может.

Чтение сохраняет до 100 000 символов извлечённого текста страницы внутри исследования.
В ответ идут фрагменты до 6000 символов, оценщику — заново выбранные фрагменты до 4000,
с учётом самостоятельного задания и оставшихся вопросов. `excerpted` означает, что
модели показан фрагмент; `source_truncated` — что сам извлечённый текст превысил лимит.
Это разные ограничения. Оценщик может вернуть `read_requests: [{url, focus}]`, чтобы
выбрать другой раздел уже загруженного текста без новой сетевой загрузки. Такое
дочитывание расходует бюджет чтений и возможно после исчерпания поисковых запросов.
В памяти и отчёте сохраняются признаки сокращения субтитров/распознанной речи.

Результат сохраняет прежний контракт `(results, error)`: `results` совместим
со списком и содержит `report` с запросами, происхождением источников,
ошибками, затратами обращений и причиной остановки. Для каждого материала
различаются прочитанный текст, только сниппет и недоступная страница.
Совпадающие URL объединяются с сохранением всех путей обнаружения;
точные копии прочитанного текста не выдаются как независимые источники.

Отмена и дедлайн прекращают ожидание и запуск новой работы. Уже выполняющийся
HTTP-запрос или браузерная операция могут завершиться позднее; результат
отбрасывается. Одновременно выполняется не более четырёх таких операций.
Публичные адаптеры находятся в [public_sources.py](public_sources.py).
Для YouTube работает гостевой поиск по публичной странице результатов;
последующие страницы ищутся через поисковые индексы. Для ВК, TikTok и Telegram
добавлены отдельные запросы по доменам; это не внутренний поиск площадки.
Если SearXNG не нашёл материалы направления, отдельное обращение к Serper
учитывается в том же бюджете. Страницы TikTok Discover исключаются как
агрегаторы. Русское и латинское написание названий учитываются при ранжировании.

Гостевое чтение получает точный публичный пост Telegram через виджет,
текст конкретного поста ВК, описание видео YouTube/TikTok и, когда они
отданы публичной страницей YouTube, субтитры с временными отметками.
Описание и метаданные имеют статус `metadata_only` и не считаются прочитанной
речью видео. Поле `report.coverage` показывает найденные материалы, чтения и
описания по каждой площадке. Отсутствие выдачи не означает отсутствие материалов.

Социальные адаптеры не используют аккаунты, `.netrc`, сохранённые cookies или
браузерные профили; переходы проверяются на доступ к частной сети. При отказе
гостевого чтения содержимое не подменяется текстом страницы входа. Гостевой
транспорт [guest_transport.py](guest_transport.py) учитывает текущие настройки
прокси приложения: сначала настроенный HTTP/SOCKS5-прокси, затем прямой маршрут
при сетевом сбое/отказе прокси. Режим «Напрямую» явно отключает прокси.
Публичные страницы и субтитры используют один транспорт. Учётные данные прокси
не передаются модели и не включаются в диагностику; старое логирование адресов
прокси также скрывает логин и пароль. Допустимы только временные анонимные
cookies, полученные внутри текущего запроса/сеанса; файлы браузера не читаются.

Для готовых субтитров подключена бесплатная локальная библиотека
[youtube-transcript-api](https://github.com/jdepoix/youtube-transcript-api)
через [youtube_captions.py](youtube_captions.py). Она не скачивает видео и не
запускает распознавание аудио. Длительность ролика сама по себе не требует
ожидания его воспроизведения. Ограничения по умолчанию: 18 секунд на источник
(включая прокси, прямой маршрут и субтитры), 8 HTTP-попыток и 8 МБ суммарно,
до 1 МБ на файл субтитров, до 2 попыток получения субтитров за поисковый вызов.
Текст субтитров ограничен 60 000 символами/2500 сегментами, сокращение явно
отмечается. Политика задаётся `SearchBudget.max_transcripts` и
`SearchBudget.max_read_seconds`. Успех кэшируется на час, ошибки — на минуту;
кэш в памяти ограничен 128 записями и разделён по маршрутам. Общий бюджет
исследования и отмена имеют приоритет над завершением чтения источника.

Диагностика `transport` у источника содержит число обращений, объём и исходы
маршрутов без адреса прокси или паролей. Таймаут прямого `t.me` при успешном
ответе через прокси указывает на проблему маршрута, а не на необходимость входа.
TgWsProxy/MTProto-прокси для Telegram Desktop не является обязательным компонентом:
чтение публичного `t.me` идёт по HTTPS через обычный прокси.

Для TikTok добавлен [yt-dlp](https://github.com/yt-dlp/yt-dlp): сначала готовые
субтитры, затем выборочное локальное распознавание речи. До одного задания
распознавания за поиск (`max_audio_jobs`), ролик до 180 секунд, обрабатываются
только первые 90 секунд звука, загрузка до 8 МБ, общее время источника — до
25 секунд (`max_media_seconds`). Частичный результат явно помечен и содержит
временные отметки. Стандартная модель — многоязычная Whisper tiny; она должна
быть заранее подготовлена в кэше Hugging Face. Во время поиска модель не
скачивается; другую локальную модель можно указать в `KID_SEARCH_WHISPER_MODEL`.
Распознанный текст имеет тип `speech_transcript`, отдельный от готовых субтитров.
Кадры, OCR и поиск публикаций по автору не выполняются.

TikTok остаётся дополнительным направлением: по явному упоминанию в запросе либо
выбору модели/планировщика, без обязательного обращения при каждом поиске.
Проверка восьми разных роликов и повтор после исправлений описаны в
[отчёте TikTok](reports/tiktok-verdict-2026-10-25.md). На повторе речь получена у
4 из 8; готовые субтитры не получены. Это малая выборка, не гарантия доступности.
Для поиска готовых субтитров yt-dlp вызывается с `writesubtitles=True`, но сам
экстрактор выполняется с `download=False`; загрузка видео на этой стадии не нужна.

Звук берётся из аудиодорожки минимального подходящего видеофайла: отдельный
формат TikTok `audio` может содержать только фоновую музыку и исключён.
Видеоизображение не декодируется. Работа yt-dlp и Whisper выполняется в
отдельном процессе; при таймауте завершаются также его дочерние процессы,
временные файлы удаляются родителем. Успех и ошибки кэшируются в памяти.

ВК после чтения HTML проверяется через сервисный API, если задан
`KID_VK_SERVICE_TOKEN` или приватное поле `vk_service_token` конфигурации.
Создание приложения и получение ключа автоматически не выполняются. Без
сервисного ключа API имеет статус `not_configured`. Дополнительная попытка
рендеринга JavaScript запускается в новом гостевом контексте браузера, без
сохранённого профиля; проверяются DOM и JSON-ответы для точного owner/post ID.
До одного браузерного чтения за поиск (`max_browser_reads`), в пределах общего
времени источника. Диагностика `vk_methods` сохраняется и при отказе чтения.

Выбор направлений задаётся в [search_policy.py](search_policy.py). Пять категорий —
первоисточники/общий веб, статьи, обсуждения, видео и соцпубликации — служат картой
охвата. Общий веб ищется всегда; к нему выбираются до четырёх направлений по теме.
Модель может явно задать `sources` инструмента `web_search`; пустой список означает
только общий веб. Без списка действует локальная тематическая политика без отдельного
вызова модели. Планировщик может добавить до двух направлений из разрешённого каталога
в пределах общего бюджета. Выбор сохраняется в `report.routing`.

Каталог включает YouTube, Telegram, ВК, TikTok, 4PDA/Reddit, Отзовик/IRecommend,
Хабр/vc.ru, GitHub/Hugging Face, Google Play/App Store/RuStore. Пикабу выделен в
опциональное направление: включается по упоминанию, выбору модели или планировщика.
Общий веб может находить любые индексируемые сайты. Уточняющие запросы получают место
перед дальнейшей пагинацией. Ранжирование учитывает название искомого объекта и его
русское/латинское написание; это эвристика релевантности, а не проверка достоверности.

[discussion_reader.py](discussion_reader.py) читает публичные обсуждения с отдельными
ссылками на комментарии. GitHub issues/PR: описание и первая/последняя страницы
комментариев; Reddit: ограниченное дерево публичного JSON; Хабр: статья и отдельная
страница комментариев; 4PDA: доступные тела сообщений и последняя страница той же темы.
До трёх HTTP-попыток и 3 МБ на чтение, до 30 комментариев; пропуски и сокращения
помечаются `thread_truncated`. Комментарии выделяются как мнения пользователей.
При блокировке или отсутствии комментариев используется доступное обычное чтение
страницы с диагностикой отказа. Полного обхода веток, PR review comments и внутренних
поисковых API площадок нет.

Форматы публичных страниц могут меняться. Полного охвата, распознавания длинных
видео, сохранения и возобновления исследования пока нет.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests
cd UI
npm run typecheck
npm run build
```

Кнопка резервного копирования сохраняет архивы в приватный каталог данных.
`python restore_backup.py` показывает план восстановления последнего архива;
`python restore_backup.py --apply` выполняет восстановление. Запускайте через Python из `.venv`.
Рабочие заметки автора находятся в соседнем каталоге `../kid-docs`; для установки они не нужны.

Приложение рассчитано на локальную работу: UI слушает `127.0.0.1:3000`,
а внутренний мост — `127.0.0.1:5000`. Не выставляйте эти порты в интернет.
